## Owner mode controls and compact web console

A changed selection opens a short impact review and requires **Apply change**. Requests remain visible; Activity and Devices are collapsed by default. Polling preserves unsaved edits, conflicting versions require fresh review, duplicate submissions are blocked, and a lost POST response can reconcile a subsequently confirmed server mode without an automatic retry.

Only the separate owner listener accepts strict versioned policy changes. A successful edit increments the policy version and writes a bounded typed owner change journal in the same staged settings write. New authority remains suspended until persistence, transactional retirement of old challenges/permits/requests/sessions, and private browser-session cleanup complete. An unused old execution is cancelled; possible delivery becomes OUTCOME_UNKNOWN and quarantines the runtime. Persistence or cleanup faults retain the old live config and suspend authority; unrelated writes cannot overwrite the staged intent, and only an exact-intent retry repairs the fault. ## Security release gate

Real account enrollment stays disabled until all ten design §53 gates pass. In particular, an agent running with this workspace's unrestricted host access cannot meet the trusted-runtime isolation assumption. Complete isolated deployment, physical-device tests, owner recovery, vault review, and a reviewed real-service adapter before enabling production functionality in a future audited change.

Protocol format choice: the design suggests CBOR/COSE. This implementation uses a versioned, strict canonical JSON byte protocol with ECDSA/SHA-256 DER. Both TypeScript and Swift have shared canonical fixtures; any protocol change requires new versioned fixtures and replay/binding tests.
